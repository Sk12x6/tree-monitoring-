Introduction

DHT22 Temperature & Humidity Integration

This guide walks you through the complete integration of a DHT22 temperature and humidity sensor into the existing ArborGuard tree-monitoring system. The DHT22 gives you real-time environmental data — critical for understanding whether a tree is under heat or drought stress, and for providing environmental context alongside vibration/sound cutting alerts.

Already using DHT22? The base ArborGuard code already has DHT22 reads in the loop. This guide formalises the integration with correct timing, non-blocking reads, calibration offsets, and Telegram reporting — things a quick port often misses.
⚠
DHT11 vs DHT22: These sensors look identical but are NOT interchangeable in code. DHT11 uses a different protocol. If your sensor is labelled DHT11, change DHTTYPE DHT22 to DHTTYPE DHT11 in the code. However, DHT22 is strongly preferred — it has twice the accuracy and a much wider temperature range.

Step 3

Programming Steps

3a — Install the DHT library

Open Arduino IDE Library Manager

Go to Sketch → Include Library → Manage Libraries… (or press Ctrl+Shift+I). The Library Manager panel will open on the left side.

Search and install "DHT sensor library"

Type DHT sensor library in the search box. Find the one by Adafruit and click Install. When prompted to install dependencies, click "Install All" — this also installs Adafruit Unified Sensor which is required.

Verify installation

After installation, both DHT sensor library and Adafruit Unified Sensor should appear with a tick (✓) in the Library Manager. You're ready to include them in code.

3b — Library includes and sensor definition

These lines go at the very top of your sketch, with the other #include statements.

ArborGuard.ino — top of file 
#include <DHT.h>

// ================================================================
//  DHT22 SENSOR DEFINITION
// ================================================================
#define DHTPIN   27         // GPIO 27 — single data wire
#define DHTTYPE  DHT22      // IMPORTANT: DHT22, not DHT11
DHT dht(DHTPIN, DHTTYPE);

3c — Global state for DHT22 readings

The DHT22 must not be polled more than once every 2 seconds. We use millis() timing so the main loop runs at full speed without blocking. Place this block after your namespace declarations.

Global state — add after existing namespace blocks 
// ================================================================
//  DHT22 STATE
// ================================================================
namespace DHTState {
  float    temp         = 0.0f;   // last valid temperature °C
  float    hum          = 0.0f;   // last valid humidity %
  bool     valid        = false;  // false until first successful read
  uint32_t lastRead     = 0;
  uint8_t  errorCount   = 0;
  constexpr uint32_t READ_INTERVAL = 2000; // DHT22 max rate: 0.5 Hz
  constexpr float    TEMP_OFFSET   = 0.0f; // adjust after calibration
  constexpr float    HUM_OFFSET    = 0.0f; // adjust after calibration
}

3d — setup() initialisation

Inside setup() — add after Wire.begin() 
dht.begin();
delay(2000); // DHT22 needs 2s after power-on before first read
Serial.println("[DHT22] Sensor initialised on GPIO 27");

3e — Non-blocking DHT read function

Call this once at the top of loop(). It checks elapsed time, reads the sensor only when due, validates the result, and updates the global state. It never blocks for more than a few microseconds.

New function — add before setup() 
// ================================================================
//  DHT22 TASK — call every loop(), non-blocking
// ================================================================
void dhtTask(uint32_t now) {
  if ((now - DHTState::lastRead) < DHTState::READ_INTERVAL) return;
  DHTState::lastRead = now;

  float t = dht.readTemperature();
  float h = dht.readHumidity();

  if (isnan(t) || isnan(h)) {
    DHTState::errorCount++;
    Serial.printf("[DHT22] Read failed — error count: %d\n", DHTState::errorCount);
    // Keep using last valid values (DHTState::temp / hum unchanged)
    return;
  }

  // Apply calibration offsets (set to 0.0 until you calibrate)
  DHTState::temp  = t + DHTState::TEMP_OFFSET;
  DHTState::hum   = h + DHTState::HUM_OFFSET;
  DHTState::valid = true;
  DHTState::errorCount = 0;

  Serial.printf("[DHT22] Temp: %.1f°C  Hum: %.1f%%\n",
               DHTState::temp, DHTState::hum);
}

3f — Updated loop()

Add one line to call dhtTask() at the top of your main loop. Then use DHTState::temp and DHTState::hum everywhere instead of calling dht.readTemperature() directly.

loop() — updated structure 
void loop() {
  uint32_t now = millis();

  dhtTask(now);      // ← ADD THIS LINE (first in loop)
  wifiTask(now);

  // ... rest of loop unchanged
  if ((now - tSensor) >= Timing::SENSOR_MS) {

    // Use DHTState values — already updated by dhtTask()
    S.temp  = DHTState::temp;
    S.hum   = DHTState::hum;

    S.soilF  = readSmooth(SOIL_PIN);
    S.vibF   = readSmooth(VIB_PIN);
    S.soundF = readSmooth(SOUND_PIN);
    S.luxF   = lightMeter.readLightLevel();
    tSensor  = now;
  }

  updateDisplay(now);
  buzzerUpdate(now);
  detectTreeCutting(now);
  handleAlerts(now);
}

Step 4

Calibration Instructions

The DHT22 is factory-calibrated and accurate within ±0.5°C and ±2–5% RH out of the box. For most tree monitoring purposes, no calibration is required. However, if you want to verify accuracy or apply a correction offset, follow these steps.

Method 1 — Compare against a reference (recommended)

Get a reference measurement

Use any one of: a calibrated thermometer / hygrometer, your phone's built-in weather app (indoors), a kitchen thermometer, or another DHT22 module for cross-comparison. Let the reference device and DHT22 sit in the same room (away from any heat source or direct sunlight) for 15 minutes before taking readings.

Read both values simultaneously

Open Serial Monitor at 115200 baud and read 5–6 DHT22 temperature values over about 30 seconds. Calculate the average. Note the reference device reading at the same time.

Serial Monitor — example calibration session
[DHT22] Temp: 27.3°C Hum: 58.0%
[DHT22] Temp: 27.4°C Hum: 57.8%
[DHT22] Temp: 27.4°C Hum: 58.1%
[DHT22] Temp: 27.3°C Hum: 57.9%
Average → Temp: 27.35°C · Reference thermometer: 27.0°C
→ Apply TEMP_OFFSET = -0.35f
Calculate and apply the offset

Offset = Reference value − DHT22 average. A positive offset means the DHT22 reads low; negative means it reads high. Apply it in the code:

DHTState namespace — update offsets after calibration 
constexpr float TEMP_OFFSET = -0.35f;  // example: DHT reads 0.35°C high
constexpr float HUM_OFFSET  = +2.0f;   // example: DHT reads 2% RH low

Method 2 — Ice water check (temperature only)

This verifies the sensor at the known 0°C reference point. Place the DHT22 in a sealed zip-lock bag (to keep it dry), then immerse the bag in a cup of ice water for 5 minutes. The reading should stabilise to approximately 0–1°C. If it reads 3–4°C or more, the offset is significant.

⚠
Keep the sensor dry! The DHT22 is NOT waterproof. If doing the ice water test, ensure it is completely sealed in a dry bag. Water droplets on the sensor surface will cause inaccurate readings and can permanently damage it.

Acceptable operating ranges

Temperature — deployment range for tree monitoring
−10°C (cold stress) 15–35°C (optimal) >40°C (heat stress)
Humidity — typical outdoor range
<30% (drought) 50–80% (healthy) >90% (disease risk)
ℹ
Humidity near 100%: In heavy rain or fog, the DHT22 may read close to 100% RH for extended periods. This is correct, not a malfunction. Condensation on the sensor body is normal outdoors and clears when humidity drops.
Step 5

Testing the Sensor

Test in three layers — Serial output first, then OLED display, then Telegram message. Each layer depends on the one before it.

Layer 1 — Serial Monitor verification

Upload the code and open Serial Monitor at 115200 baud. Within 2–3 seconds of boot, you should see valid DHT22 readings:

Expected Serial output on boot
[DHT22] Sensor initialised on GPIO 27
[WiFi] Connecting to YourNetwork...
[WiFi] Online — IP: 192.168.1.105
— 2 seconds pass —
[DHT22] Temp: 27.4°C Hum: 62.0%
[Vib: 48 Sound: 91 Soil: 1820 Lux: 312]
[DHT22] Temp: 27.3°C Hum: 62.1%
⛔
If you see nan or "Read failed": This means the sensor is not responding. Check wiring first — is GPIO 27 connected to the DATA pin? Is VCC on 3.3V? Is GND connected? If using a bare sensor, is the 10kΩ pull-up resistor between VCC and DATA? If all wiring is correct, try a longer startup delay (delay(3000) in setup).

Layer 2 — OLED display check

Once Serial reads are confirmed, look at the OLED screen. Line 2 should show live temperature and humidity. If it shows "T:-- H:--", the sensor is still warming up — wait 3–5 seconds. If it stays stuck on dashes, the DHTState::valid flag is never being set — revisit the dhtTask() function.

Troubleshooting guide

SymptomLikely causeFix
Readings are nan constantly No pull-up resistor / wrong pin / bad wire Check GPIO 27 is connected to DATA, not VCC or GND. Add 10kΩ pull-up if bare sensor.
First read is always nan, then works DHT22 needs 2s warmup after power-on Normal — delay(2000) in setup() handles this. Don't call readTemperature() before 2s.
Occasional nan every few minutes Timing — loop() calling DHT too fast (<2s) Confirm dhtTask() only reads when millis() - lastRead >= 2000. Check no other code calls dht.read().
Humidity reads 0% or 100% all the time Sensor damaged by moisture / wrong power Check VCC is 3.3V, not 5V. If exposed to condensation, let it dry for 24h in a warm room.
Temperature reads ~4°C too high ESP32 board self-heating affecting sensor Mount DHT22 at least 5 cm away from the ESP32 chip using extension wires. Apply a negative TEMP_OFFSET after re-measuring.
OLED shows "T:-- H:--" stuck DHTState::valid never set to true Check Serial — if "Read failed" appears every 2s, it's a hardware issue. If no DHT lines appear, dhtTask() is not being called in loop().
Telegram alert missing Temp/Hum Old message format not updated Confirm Step 3h code changes are in place. Rebuild and re-upload the sketch.
✦
Self-heating note: The ESP32 generates heat during WiFi transmission. If the DHT22 is mounted directly on the same board or very close to the ESP32 chip, it may read 2–5°C higher than actual ambient temperature. The fix is simple: use 3 jumper wires to mount the DHT22 sensor at least 5–10 cm away from the ESP32, attached to the tree bark itself rather than the main circuit board.
✦
Next upgrade path: Log temperature and humidity over time to SD card or to a Google Sheet via WiFi. Tracking a week of data lets you correlate soil moisture dryness with humidity drops, giving you early drought detection beyond just the instantaneous soil sensor reading.
